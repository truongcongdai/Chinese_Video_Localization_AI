# Reup Agent, two speakers, and extractive shorts

## Scope and installation

The **Reup Agent** tab finds existing videos, sends them through the normal localization job, prepares a YouTube publishing pack, and can upload through the connected YouTube account. It does not call the old AI video creator. The old **AI Channel Agent** tab and its feature flag remain separate. Existing one-voice jobs keep their previous defaults.

For a low-VRAM computer, install `requirements-reup.txt` in a fresh virtual environment and keep the normal FFmpeg/ffprobe installation. `requirements.txt` retains the project's CUDA wheels for existing deployments; `requirements-cuda.txt` lets a reup installation opt in to those wheels. `requirements-creator.txt` contains the optional image/video generation packages. Do not install the creator profile just to use Reup Agent. On a 1660 Super, start with `WHISPER_DEVICE=cpu`, `OCR_DEVICE=cpu`, `ENABLE_DEMUCS=false`, and one localization job at a time. The default Whisper, OCR, TTS and render stages can still be slow on CPU; optional local AI avoids paid model APIs, but source download, Edge TTS and publishing still require network access and may be rate-limited by their providers.

Two-speaker automatic detection is optional. Install `requirements-diarization.txt`, accept the model's terms, save a compatible `pyannote/speaker-diarization-community-1` model to a local directory, and set `DIARIZATION_MODEL_PATH` to that directory. The app never downloads the model on startup. `DIARIZATION_DEVICE=cpu` avoids using the 1660 Super for diarization. Choose **Tự nhận diện (local)** and map `speaker_0` and `speaker_1` to installed Edge TTS voice IDs. Speaker turns are assigned by overlap with timed dialogue. Mixed/uncertain turns are flagged for subtitle review; one ASR sentence is not falsely split into two different text lines. **Gán thủ công** stops for subtitle review so the operator can enter speaker IDs before rendering. For a long video, local diarization can use significant RAM and time.

## Source to upload

1. Connect the intended YouTube channel using the existing account settings. Confirm that source rights permit reuse and publication. The profile's rights check is required before autonomous upload.
2. Open **Reup Agent**, enter a channel topic, optional search keywords, excluded words, and/or direct HTTPS source video or channel URLs. Choose YouTube, Bilibili and/or Douyin search. Save the profile, then click **Tìm nguồn ngay**. Search reads metadata first; the existing localization downloader fetches video only after a run starts. Douyin may need `DOUYIN_COOKIES_FILE` and Playwright Chromium. CAPTCHA and blocked sources produce warnings; no bypass is attempted.
3. Choose **Bấm xử lý từng nguồn** for manual starts, **Tự xử lý, duyệt trước khi đăng** for prepared uploads, or **Tự xử lý và đăng theo cấu hình** for autonomous runs. Periodic scans start only when **Bật quét** is checked. Existing creator workflows are unaffected. The ready state in assisted/manual modes requires **Duyệt đăng**. You may confirm source rights in the profile after discovery, but must do so before approving that run; autonomous mode requires rights and a connected matching channel before it can be enabled. For public scheduled uploads, enter timezone and local publish time; scheduling is sent to YouTube as a private upload with `publishAt`. A local upload cap and duplicate-source checks are enforced.
4. Use the run list to inspect status, linked job ID, short preview, title and metrics. **Xem gói đăng** shows the prepared thumbnail, title, description, hashtags and tags before approval. A pause stops the agent between stages; it does not stop an already running localization job or remove a remote YouTube upload. A restart can resume saved upload sessions. A failed localization job must first be retried from normal job history, then retried in the run list.

The agent uses a fallback metadata pack without an LLM, or an already installed Ollama model when **AI local** is selected. The local model is also needed for *automatic* plot-based short selection; the Ollama path explicitly requests CPU and unloads after use. Source discovery and the package preview do not require an Ollama model. Review title, description, hashtag and thumbnail before approving public uploads: metadata quality depends on the available transcript and model.

## Long video to short

Finish a localization job, then open **Tạo một short** in Reup Agent. Enter its job ID and request a timeline. With a local Ollama model, the selector returns IDs of actual transcript events and extracts their original timestamps. Without a model, it returns position-sampled highlights clearly marked for review; those are not claimed to summarize the plot. Adjust or add cuts in chronological order, preview source scenes, and click **Dựng short**. The cut list is bounded to 30 entries and 10–180 seconds. FFmpeg cuts the localized video into a 720×1280 letterboxed short while retaining its translated audio and burned subtitles. It saves the new short and a separate publishing pack without changing the original long video. This is an extractive cut, so scenes with no timed dialogue need manual cut selection and scene transitions are hard cuts.

## Operations and limits

Run one web worker process for the built-in 30-second agent loop. SQLite checkpoints survive application restarts, but this is not a distributed queue. The owner-scoped profile/run data and SQLite migrations are additive. No automatic profile is enabled by default. YouTube OAuth credentials and quota are still required; platform availability, terms, licensing and YouTube reuse/monetization decisions are external to this software. Automatic upload does not guarantee public visibility: the agent records YouTube's actual privacy and processing status and warns if a requested public or scheduled item remains private.

Before using autonomous publishing, validate a few representative source videos with manual/assisted mode, check speaker attribution, short cuts, thumbnails and the actual YouTube account. The implementation tests use mocks for remote providers and a synthetic FFmpeg video; they do not constitute a live upload validation.

## Product priorities after the first pilot

1. Measure completion rate, processing time per source minute, speaker corrections, duplicate attempts and upload failures on one niche and one owned channel. Keep the assisted approval mode until those rates are acceptable.
2. Add a visual scene/keyframe selector for videos with little dialogue. The current short selector uses timed transcript events and needs human cuts for visual-only events. Overlapping speech also needs better source separation/ASR, beyond speaker diarization.
3. Evaluate discovery availability against real YouTube, Bilibili and Douyin pages and account conditions. Their search/cookie behavior can change; each connector should expose health, backoff and pagination before increasing daily volume.
4. Add perceptual fingerprints to catch re-encoded duplicates across platforms, and store evidence of reuse permission per source. Current duplicate protection uses canonical platform IDs and exact source-file hashes.
5. Split the large legacy web/app and store modules along stable feature boundaries as changes are made. The new reup router and repository are already isolated; a wholesale refactor would add regression risk without improving this pilot.
6. Add YouTube Analytics metrics such as CTR and retention after the upload path is proven. Current read-only monitoring stores public video statistics, not detailed Analytics data.
